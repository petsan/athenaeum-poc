# Acceptance Criteria — Highest-Risk Tasks

`body-design.md` Section 11's ~47 tasks mostly describe intent ("verify identical state reconstruction on resume") without a checkable pass/fail line. Full coverage of every task is future work; this covers the tasks flagged highest-risk in the original backlog, since those are the ones worth pinning down precisely before further implementation.

| Task | Acceptance criterion |
|---|---|
| 7a — content-addressed storage | `get()` on unmodified content returns identical bytes; `get()` on content modified after write raises `IntegrityError`; two `put()` calls with identical bytes return the same key and do not create a second stored object. *(All three — implemented and passing in `test_content_addressed.py`.)* |
| 7 — checkpoint log | `verify_chain()` returns `True` on an untouched chain of N>1 entries; raises on a chain with any entry's metadata OR payload corrupted; `last_good_snapshot_id()` returns the entry immediately before a corrupted one. *(Implemented and passing in `test_checkpoint.py`.)* |
| 12/13 — single-unit runner, resume | A unit killed after round K and resumed via a **freshly constructed** runner/log pair (no shared in-memory state) continues at round K, not round 0; the final committed state is identical to an uninterrupted run. *(Implemented and passing in `test_runner_resume.py`, `test_brain_integration.py`.)* |
| 18 — time-sliced scheduler | Given units of equal priority, `process_one_round()` processes them in FIFO submission order; given unequal priority, always pops the highest-priority queued unit first, verified even when a lower-priority unit was submitted earlier. *(Implemented and passing in `test_multi_unit.py`.)* |
| 19 — cross-unit visibility | A write committed by unit A's round N is present in the shared state passed to unit B's round N+1 (not merely "eventually" — the very next round). *(Implemented and passing.)* |
| 20a — expected-version + idempotency | A write with a stale `expected_version` raises `ConflictError` and does not mutate state; a write retried with the same `idempotency_key` returns the original result and does not increment the version a second time. *(Implemented and passing in `test_concurrency.py`.)* |
| 23d — VRAM LRU eviction | Requesting a model that doesn't fit in remaining VRAM evicts the least-recently-*requested* (not least-recently-loaded) model first; a model touched by a request is protected from eviction ahead of one that wasn't. *(Implemented and passing in `test_model_serving.py`.)* |
| 23g — sandbox isolation *(not yet implemented)* | An execution attempting network access fails closed with no partial success; an execution exceeding `cpu_time_limit_seconds`/`memory_limit_mb` is terminated and produces no `executable`-typed claim; state does not persist between two separate invocations. **Blocked on the dedicated security review flagged in `body-design.md` Section 4.6 — do not implement against this criterion alone without that review.** |

## Remaining backlog tasks (extended this session)

| Task | Acceptance criterion |
|---|---|
| 1 — config loader | Loading a config missing no required fields succeeds; `working_set_floor_gb >= local_dram_gb` raises `ConfigError`; `disallow_paid_apis: false` raises `ConfigError` (hard invariant, not a settable policy). *(Implemented and passing in `test_config.py`.)* |
| 2 — core data schemas | Every one of the five schemas round-trips through `to_dict()`/`from_dict()` with full equality, including default-valued fields. *(Real gap, closed this session — `test_schemas.py`.)* |
| 3 — work-unit/round-handler interfaces | A `WorkUnit` constructed with only required fields defaults to `status="queued"`, `round_index=0`; a `RoundResult` with no `proposed_writes` defaults to an empty dict, never `None`. *(Implemented via dataclass defaults; exercised indirectly by every runner/scheduler test.)* |
| 4 — Tier 1 boot-load | Config loaded from a fixed local path is available before any Tier 2/3 access is attempted; a missing boot config raises rather than silently defaulting. *(Implemented via `Config.load()`; no dedicated boot-sequence test yet — worth one once a real boot entry point exists.)* |
| 5/6 — tiered read/write | A `put()` while Tier 2 is reachable writes to both tiers; a `put()` during `simulate_tier2_outage()` still succeeds and is readable both during and after the outage without a manual failback call. *(Implemented and passing in `test_tiered.py`.)* |
| 8 — resource monitor | `get_state()` reflects the most recent `set_state()` call exactly, with no interpretation applied at the monitor layer. *(Real gap, closed this session — `test_resource_monitor.py`.)* |
| 9 — scale-down reaction rules | `target_concurrency` never returns less than 1 regardless of `cores_available`, including 0; `should_suspend` is `True` exactly when `dram_headroom_gb < working_set_floor_gb`, tested at, above, and below the boundary. *(Closed this session.)* |
| 10 — checkpoint-and-suspend on DRAM breach | A running `WorkUnit`, when the monitor reports headroom below the floor, has its round execution skipped (not merely flagged) until headroom is restored, and resumes with no rounds lost or duplicated. *(Genuine end-to-end test, closed this session — distinct from Task 9's pure-function check.)* |
| 14/15 — fetch + license check, parse/normalize | A paid, robots-disallowed, or unlicensed source is rejected with a specific machine-readable reason, never silently dropped; an accepted source's content is durably, tamper-evidently stored, and its `ProvenanceEntry.content_hash` round-trips through the CAS. *(Closed this session — `test_ingestion.py`, using fixture sources in place of real network fetch, same substitution pattern as `MockBackend`.)* |
| 16 — ingestion as scheduled work unit | Ingestion runs through the exact same `WorkUnit`/`SingleUnitRunner` path as any other work — no special-cased scheduler branch. *(Closed this session — `test_ingestion_as_work_unit.py`.)* |
| 17 — one-time seed load | A batch containing both acceptable and rejected sources ingests every acceptable one and skips (not fails) every rejected one. *(Closed this session — `test_ingestion.py::test_seed_load_skips_rejected_without_failing_the_batch`.)* |
| 23a-23f — model registry, router, LRU, fallback | GPU-first routing, rejection of unadmitted models, LRU eviction under VRAM pressure, re-request protecting a model from eviction, transparent CPU fallback, tamper detection on weights before serving. *(All implemented and passing, prior session — `test_model_serving.py`.)* |
| 21/22 — CPU baseline, GPU-accelerated path *(blocked)* | Both paths must return equivalent output for the same input, verified by an automated agreement test. **Cannot be meaningfully implemented without real GPU access to compare against — the mock backends prove routing/fallback logic, not output equivalence.** |
| 23 — distributed worker dispatch *(blocked)* | A worker that disappears mid-task causes its work unit to be requeued, not lost, via a simulated worker-failure injection. **No distributed compute pool exists to test against — needs at minimum a second process/host to be meaningful, not just a mock.** |
| 24-26 — integration/fault-injection/soak *(partial)* | End-to-end cold-boot-to-completion is exercised piecemeal across existing integration tests but has no single dedicated script covering all stores at once; fault-injection covers Tier 2 loss, DRAM-floor breach, and checkpoint corruption individually but not combined; the soak test isn't implemented (needs real elapsed time, not just effort). |

**Now genuinely blocked on a real backend, not just unscheduled:** Tasks 21/22 (GPU-vs-CPU output equivalence) and Task 23 (distributed dispatch). Everything else in the original ~47-task list that doesn't require real network, GPU, or a second host is now either implemented or has a checkable criterion above.
